UI BASELINE — PHASE 1
Date: 2026-11-19
Scope: Inspection only. No application source changes.

STATUS
Initial representative baseline review complete. Coverage limitations are below.
Build and launch succeeded on iPhone 17 simulator (iOS 27.2).
The existing personalized Home configuration shows two cards and hides eight;
this is not a default-install or full-dashboard baseline.

SOURCE-CONFIRMED DIFFERENCES
1. Content surfaces
   Design/Styles.swift:10-28 applies glass, a border, and a shadow to cards.
   Design/Styles.swift:58-62 uses regular material for grouped list rows.
   Review whether the emphasis difference distracts across Home, Games, and More.
   Phase 2: establish a related family of content surfaces, retaining useful grouping.

2. Action hierarchy
   Design/Styles.swift:74-98 gives secondary pills white text and strong tint.
   Design/Styles.swift:136-160 gives primary actions white text and strong tint.
   Games/WordSearch/WordSearchControlsBar.swift:33-38 uses prominent styling for
   both Settings and Next Puzzle. Review their relative emphasis.
   Phase 3: quieter secondary actions and consistent disabled/pressed states.

3. Navigation titles
   SavedVerses/FavoritesView.swift:115 explicitly uses a large title.
   Settings/SettingsView.swift:27 and Stats/StatsView.swift:206 use inline titles.
   All three are reached from More. This is a confirmed configuration difference;
   whether Saved Verses deserves a library exception is a design decision.
   Phase 4: apply a documented navigation-title convention.

4. Small controls
   Design/HeaderBox.swift:19-23 gives the favorite heart no explicit minimum frame.
   Design/Styles.swift:105 defaults shared circular buttons to 44 points.
   Notes/NotesListViews.swift:158 sets filter chips to a 40-point minimum height.
   These are source-level differences, not measured runtime hit regions.
   Phase 3: inspect actual interaction bounds and standardize standalone targets.

EXISTING CONSISTENCY TO PRESERVE
- Shared cards already use 16-point padding and corner radii.
- Home and Books use recurring 16-point content spacing.
- NotesListCard already uses shared tab-bar clearance; it is not missing.
- Home deliberately uses its own header instead of a navigation title.
- Game colors communicate game identity and should not be flattened indiscriminately.
- iPad split views and wider layouts are deliberate adaptations.

PROPOSED RULES FOR IMPLEMENTATION (NOT YET USER-APPROVED DESIGN DECISIONS)
- Use standard adaptive materials/backgrounds for content; reserve glass emphasis
  for navigation and important controls.
- Distinguish primary, secondary, destructive, selected, and disabled actions by role.
- Aim for at least 44-by-44-point touch areas for standalone small controls,
  without requiring oversized visible icons.
- Use large titles on tab landing screens and inline titles on pushed screens;
  retain Home's custom header and explicitly document any library exceptions.
- Preserve existing shared spacing tokens; fix visible outliers rather than
  replacing every literal spacing value.
- Do not change the shared 80-point bottom clearance without runtime evidence.

RUNTIME FINDINGS AND SCREENSHOT INDEX
Screenshots are stored in UI-Baseline-Screenshots/ alongside this report.

B1 — Confirmed layout bug; highest cleanup priority
iPhone accessibility XXXL Home extends beyond the right edge. The greeting,
search field, and card content are clipped; the Welcome heading breaks awkwardly
into "Wel-" / "come" and the trailing header control is partly offscreen.
Reproduced in a settled capture with -UITesting (all Home cards visible).
Evidence: iphone-light-accessibility-xxxl-home.png.
Investigation entry points: Home/HomeView.swift:181-203,
Home/HomeScrollContent.swift:32-43, and the individual Home card header layouts.
Root cause is not yet isolated. Fix width negotiation and adaptive card headers;
do not shrink accessibility fonts to hide the problem.
Acceptance: no horizontal overflow; readable headings and reachable controls at
the same text size, with all Home cards visible, on narrow iPhone layouts.

B2 — Confirmed layout bug; highest cleanup priority
iPhone accessibility XXXL More footer squeezes its title and subtitle into a
tiny column (isolated letters and ellipses). Its controls consume the row width.
Evidence: iphone-light-accessibility-xxxl-more.png.
Source: App/AppSharing.swift:361-416 keeps icon, text, and both buttons in an HStack
and limits both text labels to two lines. MoreView pins this footer above clearance.
Proposed fix: allow a vertical text/action arrangement at narrow widths or large
text sizes, and verify that the More list remains scrollable and reachable.
Acceptance: complete readable copy and usable Share/QR controls at accessibility
XXXL on iPhone. iPad's wider version currently wraps successfully; preserve that.

These two defects should be addressed before aesthetic surface/button changes,
even though adaptive layout work was originally grouped under Phase 4.

V1 — Confirmed appearance difference; Phase 2 refinement
Home and Stats cards have a pronounced border/shadow compared with More and
Settings grouped rows. More combines a quiet list with a heavier footer card.
Evidence: iphone-light-home.png, iphone-light-stats.png, iphone-light-more.png.
Recommendation: reduce content-surface emphasis consistently. No text overlap
or unreadability is established by these captures.

V2 — Confirmed navigation difference; Phase 4 design decision
Saved Verses opens with a large title while Stats and Settings use inline titles.
Evidence: iphone-light-saved.png, iphone-light-stats.png, iphone-light-settings.png.
Recommendation: adopt the proposed pushed-screen rule or explicitly document
Saved Verses as a library exception.

V3 — Visible whitespace; Phase 4 refinement candidate, not a confirmed bug
More's footer is separated from the tab bar by a substantial empty gap, in addition
to the intentionally sparse center of this three-row screen.
Evidence: iphone-light-more.png.
Recommendation: compare bottom spacing across screen sizes before altering shared
clearance. Do not treat content scrolling behind the translucent tab bar as a bug.

V4 — Additional visual action inconsistency; Phase 3 refinement candidate
Games' recommendation uses a thin purple Play capsule, unlike shared primary
buttons. The entire recommendation card is the button, so the thin capsule does
not establish a small touch-target defect.
Evidence: iphone-light-games.png; Games/GamesViewRows.swift:133-146.
Recommendation: align the visible action cue with the app's chosen hierarchy.

V5 — Dark appearance follow-up; not a measured contrast failure
Home's verse reference, refresh time, reading date, and preview text look faint
against the dark translucent cards. Main headings and verse text remain readable
in this capture. Measure contrast with actual backgrounds before classifying it
as an accessibility failure; this baseline is not a contrast compliance audit.
Evidence: iphone-dark-home.png.

LIMITATIONS / REMAINING BASELINE CHECKS
Not covered: custom photo/color content backgrounds beyond the existing gradient,
landscape and resized windows, every scrolled card, populated Saved Verses,
active game/result states, or every dark/large-text screen combination.
Small-control hit-region measurements and numerical contrast testing remain open.
Reader navigation can update ordinary reading position/statistics; no notes,
favorites, or other content were deliberately created, edited, or deleted.
No blanket accessibility or layout pass is claimed for untested configurations.
